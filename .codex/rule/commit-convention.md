# Git Commit 提交规范

## 格式

```
[类型] [版本号] [需求/Bug编号] 描述
```

## 类型

| 类型 | 用途 |
|------|------|
| feat | 新增功能需求 |
| fix | 修复 Bug |
| hotfix | 线上紧急修复（线上出现的问题） |
| opt | 项目优化（性能、代码质量、重构等） |
| docs | 文档变更 |
| test | 测试相关 |

## 必填规则

| 类型 | 版本号 | 编号 | 说明 |
|------|--------|------|------|
| feat | 必填 | 必填 | 新功能 |
| fix | 必填 | 必填 | Bug 修复 |
| hotfix | 必填 | 可选 | 线上紧急修复，编号可事后补 |
| opt | 必填 | 可选 | 优化 |
| docs | 可选 | 可选 | 文档变更可以都不带 |
| test | 可选 | 可选 | 测试相关可以都不带 |

## 示例

- `[feat] [v1.0.0]  新增用户注册接口`
- `[fix] [v1.0.0] 修复详情接口缺少 appId 过滤`
- `[hotfix] [v1.0.0] 修复线上用户无法登录问题`
- `[hotfix] [v1.0.0]  修复线上支付回调超时`
- `[opt] [v1.0.0] 优化首页列表查询性能，增加复合索引`
- `[opt] [v1.0.0] 重构支付回调逻辑`
- `[docs] 更新 API 接口文档`
- `[test] [v1.0.0] 补充订单模块单元测试`

## 规则

- 描述使用中文，简洁明了
- 版本号格式：v{主版本}.{次版本}.{修订号}，如 v1.0.0
- 一次 commit 只包含一个类型，混合变更拆分为多次 commit
