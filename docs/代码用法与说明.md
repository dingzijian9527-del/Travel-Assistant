# 旅行助手项目代码用法与说明

本文档用于说明当前项目代码如何启动、如何调用、各目录职责是什么，以及后续开发时应该改哪些文件。

## 一、项目定位

本项目是一个旅行助手系统，包含前端页面、赫兹网关、基泰克远程过程调用服务、旅行智能体调用模块、配置加载、日志、上传校验等基础能力。

当前核心能力：

- 用户登录、注册、个人资料展示页面。
- 旅行首页、发现页、行程页、个人中心页。
- 旅行智能体对话页面。
- 网关提供健康检查、配置摘要、上传校验、智能体流式对话接口。
- 智能体回复通过火山方舟大模型接口生成，网关负责流式转发。
- 用户服务和智能体服务保留基泰克服务结构，便于后续扩展为真实微服务调用。

## 二、目录说明

```text
Travel-Assistant
├── cmd                 各服务启动入口
├── api                 赫兹网关业务、路由和处理逻辑
├── conf                配置文件与配置模板
├── docs                项目说明文档
├── front               前端项目
├── idl                 节俭接口定义文件
├── kitex_gen           基泰克生成代码，不手工修改
├── pkg                 公共组件
├── rpc                 基泰克远程过程调用服务
├── go.mod              后端依赖声明
└── README.md           项目基础说明
```

重点目录职责：

- `cmd`：所有后端启动入口，包含网关、远程过程调用服务和资料导入命令。
- `api`：赫兹网关业务包，负责接收前端请求、参数校验、注册路由、中间件接入、调用公共组件。
- `front`：前端页面，当前使用跨端前端框架，运行到网页端。
- `conf`：统一配置入口，数据库、缓存、网关端口、远程过程调用地址、大模型配置都应放这里。
- `pkg/config`：使用配置读取工具加载配置。
- `pkg/bootstrap`：程序启动时统一初始化配置和日志。
- `pkg/logger`：日志组件封装。
- `pkg/ai`：旅行智能体大模型调用客户端和系统规则。
- `pkg/uploadx`：文件上传校验工具。
- `api/biz/middleware`：网关中间件，如跨域、请求编号、访问日志、异常恢复。
- `api/biz/handler`：网关控制层，只处理参数、响应和调用下游组件。
- `api/biz/validator`：通用请求参数校验。
- `cmd/user`：用户远程过程调用服务启动入口。
- `rpc/user`：用户远程过程调用服务业务实现。
- `cmd/ai-agent`：智能体远程过程调用服务启动入口。
- `rpc/ai_agent`：智能体远程过程调用服务业务实现。
- `idl`：统一接口定义，新增接口优先修改这里，再生成代码。`rpc/scaffold` 统一存放基泰克脚手架生成的构建脚本、启动脚本和生成信息。

### 一次性检查后端

```bash

```

```bash
go run ./cmd/api
```

  "service": "travel-assistant"

## 四、配置说明

配置文件：

```text
conf/config.yaml
```

配置模板：

```text
conf/config.yaml.tpl
```

配置结构代码：

```text
pkg/config/config.go
```

配置加载流程：

1. 程序启动进入 `cmd/api/main.go`。
2. 调用 `pkg/bootstrap/bootstrap.go` 中的初始化方法。
3. 初始化方法调用 `pkg/config/config.go` 读取配置。
4. 配置读取完成后初始化日志。
5. 网关根据配置启动监听端口。

智能体相关配置位于 `ai` 节点：

```yaml
ai:
  provider: ark
  api_key: ""
  base_url: https://ark.cn-beijing.volces.com/api/v3
  endpoint_id: ""
  model.goname: ""
  model: ""
  timeout: 60s
  stream: true
  system_prompt: ""
  max_prompt_chars: 2000
```

字段说明：

- `api_key`：火山方舟接口密钥，生产环境不要直接提交到仓库。
- `base_url`：火山方舟兼容对话接口基础地址。
- `endpoint_id`：火山方舟接入点编号，实际请求时优先作为模型标识传给大模型接口。
- `model.goname`：模型名称，用于配置标识和人工排查。
- `model`：旧模型字段，保留兼容；没有接入点编号时才会使用。
- `system_prompt`：旅行智能体规则。
- `max_prompt_chars`：用户单次问题最大字符数。

## 五、后端网关接口用法

网关路由注册文件：

```text
api/biz/router/register.go
```

当前接口：

```text
GET  /ping
GET  /api/v1/config
POST /api/v1/upload/check
POST /api/v1/ai-stream
POST /api/v1/ai/chat/stream
```

### 健康检查

```bash
curl http://127.0.0.1:8080/ping
```

用途：

- 判断网关是否启动。
- 返回当前服务名。

实现位置：

```text
api/biz/handler/common.go
```

### 配置摘要

```bash
curl http://127.0.0.1:8080/api/v1/config
```

用途：

- 查看当前环境、网关端口、用户服务地址、智能体服务地址。
- 不返回密钥等敏感配置。

实现位置：

```text
api/biz/handler/common.go
```

### 文件上传校验

请求示例：

```bash
curl -X POST http://127.0.0.1:8080/api/v1/upload/check \
  -H "Content-Type: application/json" \
  -d "{\"filename\":\"test.jpg\",\"size\":1024}"
```

用途：

- 校验文件名是否为空。
- 校验文件大小是否超过配置限制。
- 校验文件扩展名是否允许上传。

实现位置：

```text
api/biz/handler/common.go
api/biz/utils/upload/upload.go
pkg/uploadx/upload.go
```

### 智能体流式对话

请求示例：

```bash
curl -N -X POST http://127.0.0.1:8080/api/v1/ai-stream \
  -H "Content-Type: application/json" \
  -d "{\"user_id\":1,\"message\":\"我想去成都玩三天，帮我规划一下路线\"}"
```

请求体：

```json
{
  "user_id": 1,
  "message": "我想去成都玩三天，帮我规划一下路线"
}
```

用途：

- 接收前端用户输入。
- 校验问题是否为空、是否超过最大长度。
- 读取用户最近对话上下文。
- 调用旅行智能体大模型客户端。
- 将大模型返回内容以流式文本返回给前端。
- 模型调用成功后保存最近上下文，方便连续追问。

实现位置：

```text
api/biz/handler/ai_stream.go
pkg/ai/client.go
pkg/ai/rules.go
```

注意：

- 网关不再本地拼装模板化旅行答案。
- 具体回复内容由大模型根据系统规则和上下文生成。
- 如果模型配置不完整或调用失败，只返回模型暂不可用提示。

## 六、智能体调用流程

智能体流式调用链路：

```text
前端智能体页面
  ↓
POST /api/v1/ai-stream
  ↓
api/biz/handler/ai_stream.go
  ↓
pkg/ai/client.go
  ↓
火山方舟兼容对话接口
  ↓
流式文本返回前端
```

关键代码说明：

- `ChatStream`：网关控制层入口，负责绑定参数、校验长度、设置流式响应头。
- `writeSmartTravelReply`：读取上下文，创建智能体客户端，调用大模型并保存回复。
- `buildAIContextMessages`：把历史对话和本次用户问题组合成大模型消息。
- `NewClient`：创建大模型客户端。
- `StreamChatWithMessages`：发起流式对话请求。
- `writeStreamContent`：解析大模型流式响应，把文本逐段写给前端。
- `DefaultSystemPrompt`：默认旅行智能体规则。

火山方舟调用要点：

- 请求地址由 `base_url` 拼接 `/chat/completions`。
- 请求头使用密钥。
- 请求体中的 `model` 字段优先使用 `endpoint_id`。
- 返回采用流式解析，读取每一行数据中的文本增量。

```text
front/src/main.js

```

页面目录：

```text

```

智能体页面调用位置：

```text
front/src/pages/ai/index.vue
```

当前智能体页面逻辑：

1. 用户在输入框输入旅行问题。
2. 点击发送后，前端把用户消息插入消息列表。
3. 前端请求 `http://127.0.0.1:8080/api/v1/ai-stream`。
4. 如果后端返回流式内容，前端逐段追加到智能体消息气泡中。
5. 如果后端不可用，前端显示服务暂不可用提示。

前端常用命令：

```bash
cd front
npm run dev:h5
npm run build:h5
```

## 八、远程过程调用服务说明

接口定义文件：

```text
idl/base.thrift
idl/user.thrift
idl/ai_agent.thrift
```

生成代码目录：

```text
kitex_gen
```

注意：

- 生成代码不要手工修改。
- 修改接口时先改节俭接口定义文件，再重新生成代码。
- 通用响应、错误码、分页等公共结构应优先放在公共接口定义中。

### 用户服务

业务实现目录：

```text
rpc/user
```

脚手架配套目录：

```text
rpc/scaffold/user
```

核心文件：

- `handler.go`：基泰克服务接口实现入口。
- `service.go`：用户业务逻辑。
- `repo.go`：用户数据持久层，目前是内存实现。
- `dto.go`：领域对象和接口返回结构转换。
- `errors.go`：业务错误封装。
- `model.go`：领域数据结构。

当前支持能力：

- 注册。
- 登录。
- 查询用户资料。
- 更新用户资料。

### 智能体服务

业务实现目录：

```text
rpc/ai_agent
```

脚手架配套目录：

```text
rpc/scaffold/ai_agent
```

核心文件：

- `handler.go`：基泰克服务接口实现入口。
- `service.go`：智能体业务逻辑。
- `repo.go`：对话记录持久层，目前是内存实现。
- `dto.go`：领域对象和接口返回结构转换。
- `errors.go`：业务错误封装。
- `model.go`：领域数据结构。

说明：

- 该远程过程调用服务当前保留本地规则回复能力，用于服务结构演示和单元测试。
- 前端智能体页面当前主要走赫兹网关的流式大模型接口。
- 后续如果要让远程过程调用智能体服务也调用大模型，应复用 `pkg/ai/client.go`，不要在业务逻辑里重复写调用代码。

## 十、开发时应该改哪里

### 新增网关接口

推荐修改顺序：

1. 在 `api/biz/handler` 新增或修改控制层方法。
2. 在 `api/biz/validator` 增加必要校验。
3. 在 `api/biz/router/register.go` 注册路由。
4. 增加对应测试。

控制层原则：

- 只处理参数绑定、参数校验、响应结构。
- 不直接写复杂业务逻辑。
- 不直接散落数据库、缓存、第三方接口调用。

### 修改智能体规则

推荐修改位置：

```text
pkg/ai/rules.go
conf/config.yaml
conf/config.yaml.tpl
```

说明：

- `pkg/ai/rules.go` 是默认规则。
- `conf/config.yaml` 是本地运行实际加载规则。
- `conf/config.yaml.tpl` 是配置模板。
- 三者语义应保持一致。

### 更换大模型配置

修改位置：

```text
conf/config.yaml
```

主要字段：

```yaml
ai:
  api_key: ""
  endpoint_id: ""
  model.goname: ""
```

注意：

- 真实密钥不要提交到公共仓库。
- 生产环境建议通过环境变量或配置中心注入。

### 新增远程过程调用接口

推荐修改顺序：

1. 修改 `idl` 下对应节俭接口定义文件。
2. 重新生成基泰克代码。
3. 修改 `rpc/对应服务/handler.go`。
4. 修改业务逻辑、持久层、转换层。
5. 增加单元测试。
6. 更新项目说明文档。

## 十二、常见问题

### 前端发送后没有回复

检查顺序：

1. 后端网关是否启动。
2. `http://127.0.0.1:8080/ping` 是否正常。
3. 前端智能体页面里的请求地址是否仍是 `http://127.0.0.1:8080/api/v1/ai-stream`。
4. `conf/config.yaml` 里的大模型密钥和接入点是否配置。
5. 后端日志是否出现模型调用失败。

### 返回“智能体模型暂不可用”

常见原因：

- 大模型密钥为空或不可用。
- 火山方舟接入点编号为空或错误。
- 网络无法访问大模型接口。
- 接入点状态异常。
- 配置文件没有被当前进程加载。

### 修改配置后没有生效

处理方式：

1. 停止后端进程。
2. 确认修改的是 `conf/config.yaml`。
3. 重新启动后端网关。
4. 再请求 `/api/v1/config` 确认当前环境和端口。

### 前端页面访问不到

检查方式：

1. 确认已进入 `front` 目录。
2. 执行 `npm run dev:h5`。
3. 查看终端输出的访问地址。
4. 默认通常为 `http://127.0.0.1:5173`。

## 十三、开发约束提醒

- 不要手工修改 `kitex_gen` 生成代码。
- 不要把真实密钥、密码、令牌提交到仓库。
- 不要在控制层堆业务逻辑。
- 不要在业务层散落数据库、缓存、第三方接口调用。
- 不要在网关里本地拼装智能体模板答案。
- 新增字段优先在节俭接口定义中声明。
- 新增依赖后执行依赖整理。
- 提交前至少执行后端测试和必要的前端构建。
