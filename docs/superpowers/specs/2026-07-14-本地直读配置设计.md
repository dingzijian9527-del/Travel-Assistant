# 本地直读配置设计

## 一、目标

让开发者在项目根目录直接执行服务启动命令时，程序自动读取本地真实配置，不再依赖配置路径环境变量或配置字段环境变量覆盖。

## 二、配置文件职责

```text
conf/config.local.yaml
```

本地真实配置文件，直接保存开发机的数据库连接串、令牌密钥、缓存账号密码和已启用第三方能力的密钥。该文件必须保持在忽略规则中，不进入版本控制。

```text
conf/config.yaml
```

可提交的示例配置文件，只包含安全示例值和空白第三方字段，不保存真实密码或密钥。

```text
conf/config.yaml.tpl
```

可复制的配置模板，字段直接使用配置值形式，不使用环境变量占位语法。

## 三、加载规则

配置加载函数接收非空路径时，始终读取该显式路径，供测试和数据初始化命令使用。

配置加载函数未接收路径时，固定按下列顺序选择文件：

1. `conf/config.local.yaml` 存在时读取该文件；
2. 本地文件不存在时读取 `conf/config.yaml`；
3. 已选中的文件读取失败或格式错误时立即返回错误，不回退到其他文件。

启动装配不再读取配置路径环境变量。配置解析不再自动读取环境变量并覆盖配置字段。

## 四、安全边界

1. 真实值只保存在本地配置文件。
2. 默认示例配置中的令牌密钥仍为受拒绝的示例值，避免遗漏本地配置时以弱密钥运行。
3. 删除现有用户级配置路径环境变量，避免旧终端配置造成理解混乱；改动后的程序即使看到该变量也不会读取它。
4. 不修改已经存在的本地真实配置内容，除非用户明确提供新的值。

## 五、修改范围

```text
pkg/bootstrap/bootstrap.go
pkg/config/config.go
pkg/config/config_test.go
conf/config.yaml.tpl
README.md
docs/代码用法与说明.md
```

不提交：

```text
conf/config.local.yaml
```

## 六、验证要求

1. 显式路径优先于自动本地配置选择。
2. 本地配置存在时，默认加载函数读取本地文件。
3. 本地配置不存在时，默认加载函数读取示例文件。
4. 环境变量不能覆盖文件中的令牌密钥或数据库连接串。
5. 本地配置语法错误时启动失败且不回退。
6. 在项目根目录直接执行用户服务启动命令时，不再出现示例令牌密钥错误。
