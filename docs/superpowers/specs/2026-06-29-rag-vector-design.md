# 2026-06-29 检索增强问答向量库接入设计

## 背景

旅行助手项目已有智能体流式对话接口，当前主要把用户问题和对话历史交给大模型生成回复。Milvus（米尔沃斯）向量数据库已经在服务器上启动，本次目标是先接入检索增强问答，让智能体回答前参考旅游知识片段。

## 目标

1. 先用项目内置的少量旅游资料跑通检索增强问答链路。
2. 用户仍通过现有智能体接口提问，前端不做必要改动。
3. 后端在调用大模型前检索相关旅游资料，并把资料放入模型上下文。
4. 检索不可用或检索失败时，智能体应降级为普通回答，不阻断用户对话。

## 非目标

1. 本次不实现文档上传和批量导入。
2. 本次不实现用户长期记忆。
3. 本次不强制依赖线上 Milvus（米尔沃斯）才能通过本地测试。

## 方案

新增 `pkg/rag` 包，封装检索增强问答能力。该包包含内置旅游知识、检索器接口、上下文格式化逻辑和一个本地可测试检索实现。后续接入真实 Milvus（米尔沃斯）时，只替换检索器实现，不影响智能体处理流程。

在配置中新增 `rag` 节点，包含是否启用、服务地址、集合名、检索数量、最低分数、嵌入维度等参数。默认启用本地内置资料检索，真实 Milvus（米尔沃斯）配置可通过配置文件切换。

智能体流式处理流程调整为：校验用户输入，组合历史对话，执行旅游资料检索，将命中的资料格式化为“参考资料”，再调用大模型流式接口。检索失败仅记录日志并继续普通对话。

## 数据流

```text
前端智能体页面
-> 网关 ChatStream
-> 校验用户问题
-> 构造历史消息
-> 检索旅游知识片段
-> 拼接参考资料上下文
-> 调用大模型流式接口
-> 返回流式回复
```

## 内置知识

先内置成都、杭州、北京、上海、广州、三亚等城市的少量旅游资料。每条资料包含标题、城市、标签和正文。示例资料用于开发、测试和演示完整链路。

## 错误处理

1. `rag.enabled=false` 时跳过检索。
2. 检索器返回错误时记录日志，继续调用大模型。
3. 没有命中资料时不拼接参考资料。
4. 参考资料会明确标注为“可参考资料”，避免伪装成用户原始问题。

## 测试策略

1. 测试配置默认值和配置读取。
2. 测试内置资料能根据旅游问题返回相关片段。
3. 测试检索结果会被拼进大模型上下文。
4. 测试检索失败时仍能继续调用智能体。

## 后续扩展

1. 增加真实 Milvus（米尔沃斯）客户端实现。
2. 增加嵌入模型接口，生成真实向量。
3. 增加管理端或命令行资料导入功能。
4. 增加用户长期偏好记忆。
